# Goblin 0.0.1 Implementation Plan

**Goal:** Ship a runnable local CLI and stdio MCP server for scanning, inspecting, auditing, reversible removal/restoration, and Codex skill configuration.

**Architecture:** Filesystem scanning and mutation planning live in a shared TypeScript core. MCP returns bounded metadata pages; the CLI exposes the same services with human-readable output. Archive/journal data is separate from skill discovery roots.

**Tech Stack:** Node.js 22+, TypeScript, official MCP SDK, YAML and TOML parsers; Node's test runner.

**Spec:** ../specs/2026-10-05-skill-manager-design.md

## Global Constraints

- Version is 0.0.1; local macOS first. No publishing or modification of the user's actual skills during tests.
- Never add instructions, hooks, or wrappers to other skills or project instructions.
- Usage times/counts remain null unless supported evidence exists; this version reports unknown.
- Fixed MCP tools; metadata only; 20 rows/page by default and 8 KiB response ceiling.
- User authorization to start implementation applies to this release; execute in this new project directory without another approval handoff.

## Review Focus

1. Shared symlinks: removing the canonical folder must not leave discovered aliases broken; restore must preserve original symlink text.
2. Ambiguous names, managed sources, unsafe state roots: refuse mutations before touching files.
3. Concurrent commands, interruption, and stale plans: keep a lock/journal and require recovery on incomplete changes.
4. Restore collision or edited archive: never overwrite newly created skills or restore unverified data.
5. Large catalogs and long names: bounded MCP pages without skill body leakage, with explicit continuation.
